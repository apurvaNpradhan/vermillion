# i18n

`@workspace/i18n` (i18next) serves native, the server and the email templates. English (`en`) is the only supported locale for now, in `packages/i18n/src/locales`. Keep i18n in place so more languages can be added later; unsupported saved/device languages fall back to English. The language picker stays hidden while only one locale is supported.

- Keys are `feature__identifier` (`exercise__title`). Plurals use i18next suffixes.
- Add every key to English. When more locales are introduced, add keys to all supported locales in the same change. `pnpm i18n:check` verifies the files agree and plurals are complete; `pnpm i18n:report` finds keys missing from the code or unused.
- Never concatenate translated fragments; use interpolation.
- Errors shown to users go through `errorMessage` from `@workspace/client`, which maps error codes to keys.
- Emails render in the recipient's saved locale.

## Locale resolution

Saved preference, then the locale cookie, then `Accept-Language` (the device locale on native), then `en`. The switcher writes the preference (when signed in) and the device setting. URLs carry no locale prefix. On the server the i18n instance is created per request, so languages never leak between visitors.

Dates and numbers use `Intl` with the resolved locale and the user's time zone.

# 0035. Remove the notes example vertical

Status: accepted (2026-11-09). Affects [0002](0002-vertical-slices.md), [0007](0007-additive-migrations.md), [0019](0019-synced-table-conventions.md), [0024](0024-test-strategy.md) and [0028](0028-native-navigation-shell.md); builds on [0034](0034-exercise-library.md).

## Context

The `notes` vertical was the template's reference for a full vertical and for a synced table: API procedures, upload handler, tombstone purge, client schema, native module, and the subject of nearly every sync test. It was always meant to be replaced by the product's first vertical. The exercise library (0034) is that vertical: it has its own synced table, upload handler, client schema, native module and tests, so keeping `notes` only adds a second, unrelated screen, tab and stream to the app.

Two facts shaped how it is removed. Migrations are additive-only (0007), so a release must not drop tables the previous release still reads, and the `notes` and `deleted_note_ids` tables hold whatever a dev or test database collected. And the sync tests were written against notes, so deleting it naively would delete the coverage of upload replay, rejected writes, conflicts, wrong account, offline queues and fault recovery.

## Decision

- **Delete the code everywhere.** `packages/api/src/notes` (procedures, operations, sync handler, limits, tombstone purge), `packages/sync/src/notes` (client schema, store, drafts, rejected-write retry), the note field caps in `packages/shared`, the `notes__*` locale keys and the unused `sync__rejected_*` keys that only the notes retry flow used, `apps/native/src/notes`, the `notes` route and tab, the `notes` stream in `powersync/sync-config.yaml`, the `Notes` OpenAPI tag, and the notes row of the sync registry, upload columns, client schema, fake database and parity expectation.
- **The tables stay (0007).** `notes` and `deleted_note_ids` remain in Postgres, in the `powersync` publication and in the existing migrations, which are untouched. Nothing reads or writes them. Their minimal Drizzle definitions move to `packages/api/src/legacy/notes-tables.ts`, which `packages/db/drizzle.config.ts` reads, so `pnpm db:generate` sees no difference and emits no DROP. Removing the publication entry would also be a schema change, so it is left alone; only the stream is removed. Dropping the tables, and the legacy file, is a separate migration in a later release, once no backup or client needs the data.
- **The sync tests move onto Custom exercises**, the one synced table a client may write. Seam 1 (`platform/sync/sync.test.ts`), the parity test, the connector, lifecycle and fake-database tests, and seam 3 (`exercise`, `races`, `compat`, `faults`, `local-store`) keep their scenarios with exercise rows: replay identity, concurrent duplicates, a mid-transaction database fault, rejected writes, ack loss, wrong account, schema window, old queued writes, offline queues, rollback of sibling ops, fault recovery. A scenario that only makes sense with soft deletes was dropped (see Consequences).
- **The pill is Home plus the switcher.** The tab bar takes a `directTabCount` (default 2, so the component stays general); `app/(app)/_layout.tsx` sets it to 1. Exercises and Settings are in the switcher's menu, as 0034 already placed Exercises. Home's headline number is now the count of exercises on the device, and its action opens the library.
- **Docs.** `CONTEXT.md` replaces the "Example vertical" entry with the exercise vertical as the reference; the guides, README and DESIGN.md point at `exercise` instead of `notes`; "Delete a vertical" in `.agents/verticals.md` now describes this removal (legacy definitions, no DROP). Earlier ADRs are history and are not rewritten; 0028 gains a one-line pointer.

## Consequences

- The app has one vertical with data, and the first tab is Home alone. Adding a fourth tab later only changes the order in the layout and, if wanted, `DIRECT_TABS`.
- **Dropped tests** (notes-specific, no exercise equivalent, because exercises are never deleted and have no tombstones): the tombstone purge and resurrection guard ("late PUT of a purged id", `deleted_note_ids` cascade), "delete wins over a later edit", "edit or create of a deleted id", "edit of a purged row", the notes store's list, search and pagination tests, the differential `watchNotes` reference-stability tests, the draft helpers' tests (the exercise form has its own draft tests) and the note rejected-write retry tests (exercise rejections are discard-only). The receipt purge half of the purge test stays.
- The ownership and DELETE cases now return exercise codes (`EXERCISE_DELETE_NOT_ALLOWED`) instead of `SYNC_ROW_DELETED`; the generic `SYNC_*` codes and their messages stay, reworded to be about "items".
- Until the tables are dropped, `notes` data sits unused in Postgres and backups, and the parity expectation still lists the tables. A future vertical with user-deletable rows will need the tombstone design again; the removed code is in git history, and `.agents/sync.md` and the synced-table guide keep the rules.
- The library list query sorts by title in memory (no index serves a case-insensitive title sort), so seam 3 asserts index use, not the absence of a sort.

## Findings

Ranked by severity. **Medium** = wrong behaviour a user will meet; **Low** = copy, layout or polish;
**A11y** = accessibility. No crashes were seen.

### Medium

**M1. Equipment in Settings ignores the workout's gym** (checklist 5)

- Steps: in a live workout, tap the gym chip (`@ MOF`) → choose **My gym** (the Session row is
  updated: `gym_id` = My gym). Minimise → Settings.
- Expected: "Equipment · My gym", showing My gym's kit.
- Actual: "Equipment · MOF" and "Gyms · MOF"; opening it shows MOF's bars and plates.
- Screenshots: `phone-qa-2026-11-27/equipment-not-session-gym.png`,
  `phone-qa-2026-11-27/equipment-mof-kit.png`.

**M2. Warm-ups screen: the reps stepper of every step is off-screen**

- Steps: live workout → exercise ⋮ → Exercise settings → Warm-up settings.
- Expected: each step shows its percentage and its reps, both editable.
- Actual: each step row overflows the card. The accessibility tree has "Fewer reps" / "More reps"
  buttons for every step, but they are past the right edge (a sliver is visible next to the "+"
  buttons). Warm-up reps cannot be changed.
- Screenshot: `phone-qa-2026-11-27/warmups-reps-clipped.png`.

**M3. Editing a ticked set skips the entry guard**

- Steps: tick a working set (55 × 6), then tap its weight cell and type 12 → next cell → 50 → Done.
- Expected: the same "Check this set" (swapped fields) as an unticked set gets.
- Actual: 12 kg × 50 is saved with no dialog. The same values on an unticked set and a tick
  correctly showed "Looks like the reps and weight are swapped" with Change / Keep as typed / Swap.
  The spec only runs the guard on tick, so a value typed into a done set is never checked.
- Also seen once, not reproduced: I tapped set 2's weight cell and the keypad edited set 1 (the
  set ticked just before). A second attempt focused set 2 correctly.
- Screenshot: `phone-qa-2026-11-27/done-set-edited-no-guard.png`.

**M4. Set numbers count warm-ups in copy and in screen-reader labels**

- Steps: an exercise with 2 warm-ups; log working set 2 well above target.
- Actual: the same-day note reads "Heavier: **set 4** beat the target by 6 reps" for the row
  labelled **2**. The accessibility labels do the same: the row shown as "1" is "Set 3, Weight
  (kg)", and "Mark set 3 done".
- Expected: the number the row shows (working sets 1–4, warm-ups "W").
- Screenshot: `phone-qa-2026-11-27/same-day-set-number.png`.

**M5. Home offers "Start workout" for the workout that is already open**

- Steps: start Upper B, minimise, go Home.
- Actual: Home's card still shows Upper B with a (secondary) **Start workout** button. Tapping it
  opens "A workout is in progress — Upper B is still going. Resume it, or discard it and start this
  one." with **Discard and start**, which restarts the same workout and throws away the logged sets.
- Expected: Home shows Resume, or nothing for the open workout (the Resume bar is already there).
  "Start empty workout" is correctly hidden.
- Screenshot: `phone-qa-2026-11-27/home-start-while-open.png`.

**M6. Slow loads in the live workout**

- After **Discard and start**, the new workout showed an empty screen with only "Add exercises"
  for 3–4 s before the exercises appeared (a user could add exercises to it meanwhile).
  Screenshot: `phone-qa-2026-11-27/discard-and-start-empty.png`.
- After resuming the workout (from Settings, after changing Appearance), the **Previous** column
  showed "–" on every row for several seconds before the values appeared. Screenshot:
  `phone-qa-2026-11-27/previous-column-loading.png`.

### Low

**L1. Plan your weeks: fast taps may drop an edit (not conclusive)** (checklist 3)

- Three "+ Week" taps ~0.7 s apart added 2 weeks; three "More weeks" taps added 2. The screen and
  the database agreed, so a tap was dropped rather than a write lost. A second run (4 taps ~0.7 s
  apart) applied all 4 after a 1–2 s delay. The store update is a read-modify-write inside one
  transaction, so the loss is more likely at the touch layer. Needs a human repro with real fast
  taps.
- Every change also takes about 1–2 s to show on screen after a preset tap.

### Accessibility

**A1. Icons are exposed as "phosphor-react-native-…-undefined"**

- Every Phosphor icon is an `SvgView` carrying the library's default `testID`
  (`phosphor-react-native-<name>-<weight>`, with `-undefined` when no `weight` prop is passed). The
  test tooling reports these as the node names on every screen: Home (`play-undefined`,
  `caret-left-regular`), Settings (every row icon), the Session (`timer-undefined`,
  `note-pencil-undefined`), Plan your weeks (`plus`, `minus`, `caret-right`). Scroll containers
  without a label aggregate them into their description. I could not confirm with TalkBack whether
  they are spoken. Fix: mark decorative icons `accessible={false}` /
  `importantForAccessibility="no"`, and pass `weight` so the id is not "undefined".

**A2. Dialogs and sheets are not modal for accessibility**

- With "Change active program?", "Check this set" or any sheet open, the whole screen behind stays
  in the accessibility tree and can be focused.

**A3. Bottom sheets expose three "seekbar" nodes**

- Each sheet adds "BottomSheet", "Bottom sheet handle" and "Bottom Sheet" as seekbars (Gorhom
  defaults).

**A4. Duplicate or vague nodes**

- "Hide photos" switch appears twice ("Hide photos" and "Hide photos, on").
- Rest days read "Day 3, Rest day, Rest day".
- Hint notes are exposed as a generic "Text view".
- Program cards and the Train hero: the cover letter ("U", "D") is read as text.

### Not a bug (from this run's data)

- The first live workout suggested 50 kg × 6 @ 7 for Overhead Press, below last time's 52.5 × 6.
  The reason was my seeding: I had tagged the Nov 19 session as a Deload week, and the engine
  correctly skipped it ("From Nov 12: 50 kg × 6, 6, 6, 5"). After I re-tagged the weeks, it
  suggested 55 kg × 5 ("Add 2.5 kg").

# Sigil roadmap research

**Start with editable starter Programs, then make it easier to adapt a Workout when the gym or the available time changes.** Both investments help users finish the first Session and return for the next one. Sigil already has the logging, history and progression needed to make those Sessions useful. An iOS Live Activity is the clearest platform gap and can move up if the beta is mostly on iPhone. For tab icons, try `HouseIcon` for Home first. Keep the barbell for Train.

This is a 22 November 2026 source review. The Sigil baseline comes from the README and the current Native routes, hooks and shared logic in this checkout. Competitor claims come from their own feature pages and help centers, starting with Hevy's feature index. Priorities and size estimates are product judgments. The review used source files and web retrieval, with no runtime or device verification. [Sigil README](../../README.md) · [Hevy feature index](https://www.hevyapp.com/features/)

## Status (2026-11-26)

What changed since this review, so the priorities below read correctly:

- **Done:** Gyms with caps, load steps and equipment-aware swaps (first half of 2); week phases
  (Build, Push, Test, Deload) with "Plan your weeks" (7); same-day adjustment and the prescription
  snapshot (second half of 6); training reminders, JSON backup, Pause workout, per-exercise unit,
  favourite exercises and the body-map filter (from the Hevy/Lyfta gap list).
- **Removed:** share links, the Shared links page and "Enter code" (4) were taken out in the
  2026-11-26 phone QA round; sharing is image cards only. Links stay a later option.
- **Next, in order:** ship the navigation round (phone pass, deploy), then starter Programs (1),
  then Health Connect writes (5; the owner is on Android, so it comes before the iOS Live
  Activity, 3). %1RM / training max with waves waits until phases have been used for a while
  ([research](percent-waves-readiness.md)).

## Priorities

1. **Now · Editable starter Programs. Medium.** Offer a small bundled library in Train and an optional suggestion after setup. Start with a two-day full-body Program and a three-day dumbbell Program. Show days, required equipment and estimated duration, then copy a selected plan into the user's library so it can be edited and run offline. Give returning lifters clear entry points to their existing manual setup and history import. The server already has a local-development seed for sample plans with fictional loads. The work here is a lifter-facing picker, production-ready plans and stable exercise references. Compare time to first finished Session and how many new users finish a second one. [Current Programs entry point](../../apps/native/src/training/programs/programs-screen.tsx) · [Development-only demo seed](../../packages/api/src/training/demo/seed.ts) · [Hevy's save-and-edit flow](https://help.hevyapp.com/hc/en-us/articles/36011518408983-How-to-Access-and-Use-Hevy-s-Routine-and-Program-Library)
2. **Now · Equipment-aware swaps and a short Workout option. Medium, in two releases.** First, let people pick named equipment lists such as Home and Gym, then rank the existing swap picker by available equipment, muscle match and exercise type. Keep separate history and loads for each lift. Later, preview a shorter Session by identifying optional accessories and respecting supersets and rest estimates. Both adaptations should use the existing explicit decision about what carries back into the Workout. Sigil's bar and plate inventory serves load calculations. Exercise eligibility needs its own input. Check time from opening the swap picker to selecting an exercise and whether users complete Sessions after using a short version. [Current kit editor](../../apps/native/src/session/plates/manage-equipment-screen.tsx) · [Current swap flow](../../apps/native/src/session/screen/session-screen.tsx) · [Fitbod locations and equipment](https://help.fitbod.me/hc/en-us/articles/34336407191191-My-Plan)
3. **Next · iOS Live Activity. Medium.** Start with the current exercise, next set, rest countdown and tap to resume. Add rest controls or a set-completion action after the state survives lock, process restart, finish and device takeover. Reuse the workout-state calculation where practical and keep the Session authoritative. Avoid sending the workout through a server just to display a local timer. User value is less unlocking and searching between sets. The cost is a native extension and lifecycle testing on supported iOS versions. [Current live workout state](../../apps/native/src/session/notifications/workout-live-state.ts) · [Hevy's Lock Screen controls](https://help.hevyapp.com/hc/en-us/articles/35649846517399-How-to-Use-Hevy-s-Live-Activity-on-iOS-and-Android) · [Apple ActivityKit](https://developer.apple.com/documentation/activitykit)
4. **Removed · Copyable Workout and Program links.** Update (2026-11-26): shipped 2026-11-24, then removed in the phone QA round; sharing is image cards only. The notes below describe the original intent if links return. The share-card ADR already anticipates links. Ship an opt-in, revocable snapshot of a plan with a preview and a copy action. Keep targets that are useful to the recipient, such as sets, rep ranges and rest. Omit private notes, photos, history and personal loads by default. Decide how to map a private Custom exercise before allowing one in a share. A copied plan belongs to its recipient. Later edits require a new snapshot, and revoking access leaves existing copies usable. Links add a public route and abuse handling. Track how many copied plans lead to a finished Session. [Share card ADR](../adr/0042-share-cards.md) · [Hevy's recipient flow](https://help.hevyapp.com/hc/en-us/articles/34953501503895-How-to-Share-Workouts-and-Routines-in-Hevy)
5. **Next · Export finished Sessions to Apple Health and Health Connect. Medium.** Begin with opt-in writes of new finished strength Sessions. Use a stable Session identity for deduplication and define what happens after edits, deletes and retries from two devices. Keep imported history and automatic backfill out of the first release, and make permission loss or failed writes visible without interrupting Finish. This provides value to people already using a health dashboard with a smaller first release than live wearable logging. [Apple workout documentation](https://developer.apple.com/documentation/healthkit/workouts-and-activity-rings) · [Android Health Connect workout guidance](https://developer.android.com/health-and-fitness/health-connect/experiences/workouts) · [Strong's Apple Health workflow](https://help.strongapp.io/article/147-sync-with-apple-health)
6. **Later · Preview the next exposure, then test within-Session adjustments. Medium to large.** The existing Workout preview shows previous values, upcoming suggestions and a reason label. Add the date and a way to open the comparison Session, so a lifter can check which performance informed the change. Then test an optional hold or reduce suggestion when actual reps or effort diverge substantially on today's earlier working sets. Keep planned sets, suggestions and actuals distinct. Avoid updating the Workout automatically, and let users dismiss suggestions for the Session. Research scheduled per-week changes only if users repeatedly clone Workouts to get them. [Current preview](../../apps/native/src/training/workouts/workout-progression-preview.tsx) · [Liftosaur progression preview](https://www.liftosaur.com/features/progressions) · [Alpha Progression reference workout and same-day adjustments](https://alphaprogression.com/en/blog/alpha-progression-progression-recommendations)
7. **Later · Week-by-week targets in a Program. Medium to large.** Today a Program has `planned_weeks`, but each Workout holds one fixed list of Planned sets, so a block such as "week 1 RPE 7, week 2 RPE 8, week 3 RPE 9, week 4 test a heavy single and halve accessories" or "deload in week 6" can only live in notes. Start with a per-week phase on the Program (normal, harder, test, deload) that adjusts each Planned set's effort target and set count for that week, shown in the Workout preview and the Session targets. Keep the Workout itself unchanged and let progression keep choosing loads. A later option is a load target as a percentage of estimated 1RM for top sets, which only pays off once phases exist. Found while building a 12-week strength-and-cut Program by hand (2026-11-24). [Planned sets](../../packages/shared/src/training/plans/planned-sets.ts) · [Progression engine](../../packages/shared/src/training/progress/progression.ts)

Defer watches until phone Lock Screen use or beta feedback makes a clear case for wrist entry. A public feed, leaderboards and coach messaging each add ongoing support and moderation. Copyable plans deliver a concrete way to train together with much less product surface. A general workout generator, recovery percentages and a scripting language are also later bets. The existing Program, progression and lighter-week rules give Sigil a narrower starting point. The README mentions food as a future direction. This training comparison gives no basis for ranking nutrition against the work above. ## Ideas beyond competitor parity

- **A private Run review.** Extend the month and year reports with a review tied to one completed Run. Show what the lifter followed, where they repeatedly swapped or skipped, and which exercises progressed using comparable Sessions. Offer to duplicate the Program and apply individually chosen edits before starting the next Run. The tradeoff is showing meaningful comparisons when exercise choices changed. Start with a factual recap and keep recommendations optional. [Run and Session definitions](../../CONTEXT.md) · [Existing report calculations](../../apps/native/src/session/report/period-report.ts)
- **Equipment-specific previous values.** Let a lifter distinguish two leg presses or cable stacks with different resistance while keeping one exercise in the catalog. Show the last comparable set for the chosen machine and keep the usual exercise history available. Start with a manually selected equipment alias, since training location alone cannot identify the machine. Keep old logs usable and suppress cross-machine load suggestions when equivalence is unclear. This makes equipment profiles useful even to people who rarely swap exercises. [Current Previous and Ghost rules](../../CONTEXT.md) · [Existing ghost calculation](../../apps/native/src/session/logging/logging-ghosts.ts)

## Native tab icons

The signed-in layout uses a floating pill with two direct destinations, Home and Train, and `CaretUpDown` for the switcher. Exercises, History and Settings are in the menu. The selected overflow destination's icon replaces the caret on the collapsed pill. Body and Muscles have no tab icon. Destination icons render at 24 with Regular at rest and Fill when selected. The UI guide already calls for an ember selection dot and semantic color tokens. [Signed-in layout](<../../apps/native/app/(app)/_layout.tsx>) · [Tab bar](../../apps/native/src/platform/navigation/tab-bar.tsx) · [Native UI guide](../../.agents/ui.md)

| Destination | Current glyph           | Recommendation                                                                                                                                                                                                  |

| Home        | `SunHorizon`            | **Try `HouseIcon` first.** The roof and doorway identify Home on the unlabeled pill, where the horizon can suggest a daily view. `HouseSimpleIcon` is quieter in Regular, with a more solid silhouette in Fill. |
| Train       | `Barbell`               | **Keep it.** It identifies strength training at a glance and is distinct from either Home pick.                                                                                                                 |
| Exercises   | `Books`                 | **Optional `BookOpenIcon`.** One open book reads as a reference at a glance. Compare its selected shape on the collapsed pill if the book spines in `Books` feel crowded.                                       |
| History     | `ClockCounterClockwise` | **Keep it by default.** `CalendarDotsIcon` is a viable alternative if the calendar becomes the main way users browse History. The clock currently covers both the chronological list and calendar.              |
| Settings    | `GearSix`               | **Keep it.** The gear is recognizable in the menu and as the selected icon on the pill.                                                                                                                         |

The proposed replacements are named exports in the installed `phosphor-react-native` 3.0.6. Each includes Regular and Fill artwork. Keep the switcher caret and test one glyph change at a time so any change in recognition can be attributed to the icon. The recommendations are based on the route roles and installed artwork.

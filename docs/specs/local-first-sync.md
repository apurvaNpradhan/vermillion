# Spec: local-first sync with PowerSync

Status: agreed decisions (2026-11-07). The five CHANGE proposals of the [adversarial review](local-first-sync-review.md) (D7, D11, D15, D18, D19) were accepted by the maintainer on 2026-11-07 and are marked amended below. Decisions are recorded in ADRs [0015](../adr/0015-powersync-self-hosted.md)–[0027](../adr/0027-sync-build-plan.md) (phase 1). Supersedes nothing.

Vermillion becomes a fitness app (training, macros, body metrics). Every user-logged record must work offline on web and native and sync through Postgres. This spec fixes the sync foundation only. No fitness schema is built here: the `notes` example vertical is the proving table.

Prior art: `~/Workspace/projects/vermillion` (the "old repo") built and measured this stack in a 12-experiment spike (its ADRs 0004–0012, 0021, 0022, read in place under `docs/decisions/`). This spec ports its results into the template's conventions (Turbo, oRPC, TanStack Start, Drizzle 1.0-rc, verticals, module hooks). Do not copy the old repo wholesale: its toolchain (Vite+, Hono RPC, varlock, SPA) differs.

## Architecture

```
 web / native                            Dokploy (private network)
 ┌──────────────────────┐  /rpc, /api   ┌──────────────────────────────────┐
 │ components           │──────────────►│ server: Hono + oRPC + Better Auth│
 │  └ module hooks      │               │  /api/auth/jwks                  │
 │     ├ Query (oRPC)   │               │  sync.credentials → { endpoint,  │
 │     └ PowerSync      │               │           token, userId,         │
 │                      │               │           expiresAt }            │
 │        useQuery      │               │  sync.upload → registry →        │
 │  local SQLite        │               │     vertical operations          │
 │  (web VFS / op-sqlite│   sync.<dom>  │ powersync-service ◄── WAL ── PG  │
 │   + SQLCipher)       │◄─────────────►│   bucket storage: powersync_     │
 └──────────────────────┘   stream      │   storage DB on the same PG      │
                                        └──────────────────────────────────┘
```

Reads: local SQLite through PowerSync `useQuery` (live). Writes: local SQLite, then the upload queue → `sync.upload` → one Postgres transaction → WAL → PowerSync → every device.

**Credential isolation (security correction):** before connecting or refreshing, compare the authenticated `userId` returned by `sync.credentials` with the database's Device owner and the current session generation. Never connect another user's stream to an existing owner's database. Reject stale async completions after sign-out/account switch. `expiresAt` must reflect the JWT expiry. These checks preserve the old connector's protection; the upload account check alone does not protect downloads.

## Synced table conventions

- `id`: UUIDv7 generated on the client (template column helper). Native needs `expo-crypto` (Hermes has no `crypto`).
- `user_id` on every user-owned row; streams filter `user_id = auth.user_id()`.
- **Soft delete** with `deleted_at`; streams exclude deleted rows; a pg-boss job hard-deletes after the retention period, which must exceed the supported offline horizon ([ADR 0019](../adr/0019-synced-table-conventions.md); 30 days is provisional). Retried hard DELETEs cause spurious rejected writes.
- Conflicts: **last upload wins, per field** (`PATCH` merges fields).
- Streams list columns explicitly, never `*`. `updated_at` stays server-side unless a screen needs it.
- Postgres `CHECK (length(...))` matching the zod caps, so a direct write cannot bypass them.
- Postgres partial index on `(user_id) WHERE deleted_at IS NULL`; a local index on every list sort key (declared on the Drizzle sqlite table). Verify plans with `EXPLAIN QUERY PLAN` on a device, not only in Node.
- Lists are paged (`LIMIT`, load more near the end) and virtualized (TanStack Virtual on web, FlashList on native). Rows are memoized by identity.
- Migrations stay additive (ADR 0007). Production order for a new synced table: migrate (includes `ALTER PUBLICATION`) → deploy the sync config → ship clients.

## Upload semantics (port old ADR 0008)

- One client CRUD transaction → one Postgres transaction, operations dispatched through a table allowlist.
- The upload names the account it was queued for; a different session gets `409 SYNC_WRONG_ACCOUNT` and the writes stay queued.
- Permanent failures (validation, authorization, oversize) become **Rejected writes** in a local-only `rejected_writes` table; the local row reverts; the queue never blocks. Temporary failures retry.
- A permanently bad op rolls back its whole client transaction; each reverted sibling is reported as `SYNC_TRANSACTION_ROLLED_BACK`.

## Replication setup (D16)

**Bootstrap** (idempotent, run with an admin URL; by `pnpm db:start` in dev, a one-shot Dokploy job in prod):

- role `powersync_replication` `LOGIN REPLICATION`
- database `powersync_storage` with its own role
- publication `powersync` (empty, owned by the app role)

**Per synced table**, in a custom Drizzle migration:

```sql
ALTER PUBLICATION powersync ADD TABLE notes;
GRANT SELECT ON notes TO powersync_replication;
```

## Observability (D17)

- **Sync diagnostics** (settings, web and native): connection state, last synced, upload queue length, rejected writes with retry/discard.
- **Slot lag job:** pg-boss, every 5 minutes, reads `pg_replication_slots`, logs lag through `@workspace/logger`, marks `/api/health` readiness degraded above a threshold.
- PowerSync readiness probe (`/probes/readiness`) as the Dokploy health check.

## Phases

Revised plan, accepted 2026-11-07 ([ADR 0027](../adr/0027-sync-build-plan.md); review section 7). Each phase ends green on `pnpm lint`, `pnpm typecheck`, `pnpm knip`, `pnpm test`, `pnpm i18n:check`, then a conventional commit on the feature branch. Early checkpoints are mergeable infrastructure, not user-shippable offline features.

1. **Contract and baseline:** security baseline patched; base commit `d624003`; upstream versions and SHAs recorded (handoff); ADRs 0015–0027 written; upload identity, error and state tables, supported offline horizon, browser shell/VFS and native key/runtime policy defined. Exit: current tests green and acceptance fixtures agreed. ADRs describe accepted decisions, not unresolved proposals as facts.
2. **Repeatable infrastructure:** Postgres logical WAL, least-privilege roles/storage/publication bootstrap, preflight/resume tests, env and deployment wiring, initial probes and alerts. Start with an empty sync config. Exit: clean boot, repeat boot and injected partial-bootstrap recovery.
3. **Real Postgres harness and minimal sync seam:** clone an immutable migrated template, isolate per-file state, explicit role/slot cleanup, remove the PGlite adapter (and update `.agents/orpc-testing.md`), scaffold a real-service test in CI and parity infrastructure. Exit: the existing API suite passes on Postgres; service-test infrastructure fails usefully on missing prerequisites.
4. **One-table server proof:** migrate notes constraints, soft delete, publication and grants, then activate its stream; JWT credentials; atomic upload and receipt handling through operations. Exit: headless round trip, ownership isolation, replay/ack-loss, rejection and rollback tests pass before platform UI work.
5. **Platform storage and lifecycle:** client schema and connector, bounded queries, web VFS and offline shell, native SQLCipher and crypto, serialized Device owner and auth switching, 401 queue preservation, rejected payload recovery, minimal diagnostic state. Exit: browser cold-restart and multi-tab tests. Pause for the native dev-client rebuild and runtime validation. No user rollout before the lifecycle tests pass.
6. **Notes UX:** module hooks, dirty-field forms, explicit loading/error/empty/sync states, bounded and virtualized lists, sign-out warning, retry/discard UI, i18n. Exit: real two-device editing, rejection recovery and session-expiry walkthrough.
7. **Fault and compatibility proof:** full seam 3 and parity CI, old-client upload and schema cases, delete races, process/slot/storage failures, cold browser and native release tests, device query plans and first-sync measurements. Exit: deterministic convergence and queue-conservation tests and a recorded native/browser support matrix.
8. **Operational handoff and privacy gate:** restore/resnapshot drill, alert delivery, runbooks, "adding a synced table" guide, `.agents/sync.md`, glossary (Device owner, Rejected write, Sync stream, Bootstrap), privacy/export/deletion/retention sign-off before real health data. Exit: deploy, rollback and recovery rehearsed; no silent divergence path without an alert or visible diagnostic state.

## Accepted requirements, by phase

Accepted 2026-11-07 from the [review](local-first-sync-review.md) (evidence and severity there). These are requirements, not pending gates. Open values are listed in the ADRs and settled in the named phase.

- **Offline web shell (D7, [0020](../adr/0020-offline-web-shell.md)); phase 1 contract, phase 5 build:** shell, lazy chunks, SQLite WASM and workers; never cache auth or RPC responses; the old SPA worker is not copied unchanged. Test a built app after closing it.
- **Upload replay and schema (D11, [0018](../adr/0018-upload-protocol.md), [0019](../adr/0019-synced-table-conventions.md)); phase 1 contract, phase 4 build:** replay identity and ack-loss behavior; a repeated PATCH must not overwrite a later device's edit; delete/update races; tombstone retention versus max offline horizon; unknown-client-schema handling.
- **Rejected writes (0018); phase 4 and 5:** enough local payload to inspect, edit and retry after checkpoint reconciliation, saved durably before acknowledging; crash tests between those steps; never log payloads; retry is a new validated transaction.
- **Dirty-field writes (0019); phase 6:** forms keep the edit-start baseline and send only intentional changes.
- **Device owner is not authorization (D13, [0021](../adr/0021-device-owner-and-account-lifecycle.md)); phase 1 contract, phase 5 build:** offline access versus reauth lock, deletion versus expiry, multi-tab switching, bounded JWT revocation window; never auto-wipe on transport errors or expired credentials.
- **Bootstrap (D16, [0023](../adr/0023-replication-setup.md)); phase 2:** ownership and CONNECT/USAGE grants, preflight, concurrent-run exclusion, resumable failure, restore procedure; reruns do not reset publication membership.
- **Monitoring (D17, [0025](../adr/0025-sync-observability.md)); phase 2 basics, phase 8 drill:** external alerts, disk and headroom, slot invalidation, recovery drill; liveness separate from readiness (`/api/health` is the current API probe, not `/health`).
- **Early proof (D18, [0027](../adr/0027-sync-build-plan.md), [0024](../adr/0024-test-strategy.md)); from phase 3:** minimum sync correctness tests, auth isolation and probes arrive with implementation, not only in phases 7–8.
- **Parity and boundaries (D10, D14, [0016](../adr/0016-client-data-layer-and-layout.md), 0024); phase 3, extended each phase:** explicit mappings, types, null/default semantics, local-only exclusions, publication membership, handlers, ownership, installed indexes; lint enforces the sync vertical boundary.
- **Native key and runtime (D15, [0022](../adr/0022-local-encryption.md)); phase 1 policy, phase 5 and 7 device tests:** key loss, backup/restore, reinstall, SQLCipher open and runtime/OTA compatibility, tested before real health data. No destructive resync while unsent or rejected work exists.
- **Privacy (D19, [0026](../adr/0026-no-e2e-and-privacy-readiness.md)); phase 8:** consent/legal basis, export, deletion propagation and retention before real health data.
